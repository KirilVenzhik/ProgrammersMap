SQL JOIN объединяет строки двух таблиц по условию ON: чем отличаются INNER, LEFT, FULL и CROSS JOIN и как не получить лишние дубликаты.

## Зачем нужен JOIN

В реляционной базе данные разложены по нескольким таблицам, чтобы не повторяться. Например, заказчики хранятся в одной таблице, а их заказы — в другой, и каждый заказ ссылается на заказчика по идентификатору. Чтобы получить заказы вместе с именами заказчиков, таблицы соединяют оператором `JOIN`. Условие соединения записывается после ключевого слова `ON`.

## Пример данных

Таблица `customers`:

| id | name |
|---|---|
| 1 | Анна |
| 2 | Борис |
| 3 | Вера |

Таблица `orders`:

| id | customer_id | total |
|---|---|---|
| 10 | 1 | 500 |
| 11 | 1 | 300 |
| 12 | 2 | 700 |
| 13 | NULL | 100 |

У Анны два заказа, у Бориса один, у Веры ни одного, а заказ 13 не привязан ни к кому.

## INNER JOIN

Возвращает только те пары строк, для которых условие истинно. Слово `INNER` можно не писать: просто `JOIN` означает то же самое.

```sql
SELECT c.name, o.id AS order_id, o.total
FROM customers AS c
INNER JOIN orders AS o ON o.customer_id = c.id;
```

| name | order_id | total |
|---|---|---|
| Анна | 10 | 500 |
| Анна | 11 | 300 |
| Борис | 12 | 700 |

Вера и заказ 13 в результат не попали: для них нет пары.

## LEFT JOIN и RIGHT JOIN

`LEFT JOIN` сохраняет все строки левой таблицы. Если пары в правой таблице нет, её столбцы заполняются `NULL`.

```sql
SELECT c.name, o.id AS order_id, o.total
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.id;
```

| name | order_id | total |
|---|---|---|
| Анна | 10 | 500 |
| Анна | 11 | 300 |
| Борис | 12 | 700 |
| Вера | NULL | NULL |

Так находят «сирот»: клиентов без заказов. Для этого добавляют `WHERE o.id IS NULL`. Сравнение `= NULL` не работает, нужен именно `IS NULL`.

`RIGHT JOIN` зеркален: сохраняет все строки правой таблицы. На практике его обычно заменяют на `LEFT JOIN`, поменяв таблицы местами.

## FULL OUTER JOIN

Сохраняет строки обеих таблиц. В нашем примере к результату `LEFT JOIN` добавится строка заказа 13 с `NULL` в столбце `name`.

```sql
SELECT c.name, o.id AS order_id
FROM customers AS c
FULL OUTER JOIN orders AS o ON o.customer_id = c.id;
```

## CROSS JOIN

Возвращает все возможные пары строк (декартово произведение) и не использует `ON`. Из 3 клиентов и 4 заказов получится 12 строк. Это полезно для генерации комбинаций, но случайный CROSS JOIN на больших таблицах легко создаёт огромный результат.

```sql
SELECT c.name, o.id
FROM customers AS c
CROSS JOIN orders AS o;
```

## Дубликаты при связи «один ко многим»

Строка клиента повторяется столько раз, сколько у него заказов: в результатах выше Анна встречается дважды. Это не ошибка, а следствие связи «один ко многим». Но если после такого соединения считать `COUNT(*)` или `SUM` по полям клиента, цифры будут завышены. Чтобы посчитать клиентов, используйте `COUNT(DISTINCT c.id)`, а суммы по заказам агрегируйте с группировкой.

## ON или WHERE в LEFT JOIN

Для `INNER JOIN` условие в `ON` и в `WHERE` даёт одинаковый результат. Для `LEFT JOIN` разница существенная:

- условие в `ON` определяет, какие строки правой таблицы подходят в пару, а строки левой всё равно сохраняются;
- условие в `WHERE` применяется после соединения и отбрасывает готовые строки, в том числе те, где правая часть равна `NULL`.

```sql
-- Все клиенты; к ним подцепляются только заказы на сумму больше 400
SELECT c.name, o.id
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.id AND o.total > 400;

-- Только клиенты, у которых есть заказ на сумму больше 400
SELECT c.name, o.id
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.id
WHERE o.total > 400;
```

Первый запрос вернёт всех трёх клиентов: Анну с заказом 10, Бориса с заказом 12 и Веру с `NULL`. Заказ 11 суммой 300 не подошёл под условие и в пару не попал. Второй запрос оставит только строки Анны (заказ 10) и Бориса (заказ 12): Вера отброшена, потому что `NULL > 400` не истинно. Фактически такой `LEFT JOIN` с условием в `WHERE` ведёт себя как `INNER JOIN`.
