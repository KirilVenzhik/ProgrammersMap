Первый коммит в Git: как git init создаёт репозиторий, git add готовит изменения в индексе, а git commit записывает их в историю проекта.

## Что такое репозиторий

Репозиторий — это проект вместе с полной историей его изменений. В Git история хранится локально, в скрытом каталоге `.git` в корне проекта. Там лежат все коммиты, ветки и служебные настройки. Удалите `.git` — и от репозитория останутся просто файлы без истории, поэтому вручную в этот каталог лучше не лазить.

У проекта в Git три места, между которыми переезжают изменения:

| Место | Что это |
|---|---|
| Рабочая копия (working tree) | Обычные файлы в папке, которые вы редактируете |
| Индекс (staging area) | Снимок файлов, который станет следующим коммитом |
| История (repository) | Цепочка уже сохранённых коммитов в `.git` |

Команда `git add` копирует изменения из рабочей копии в индекс, а `git commit` — из индекса в историю.

## Настройка перед первым коммитом

Каждый коммит хранит имя и email автора. Git берёт их из настроек, поэтому один раз задайте их для своего компьютера:

```bash
git config --global user.name "Ivan Petrov"
git config --global user.email "ivan@example.com"
```

Без этих настроек Git может отказаться создавать коммит или подставить имя и адрес, угаданные по системе, — это почти всегда не то, что вы хотели. Флаг `--global` записывает значения для всех репозиториев пользователя; внутри конкретного проекта их можно переопределить командой без этого флага.

## Первый коммит по шагам

1. `git init` превращает текущую папку в репозиторий: создаёт каталог `.git` с пустой историей.
2. `git status` показывает, какие файлы изменены, какие уже в индексе, а какие Git вообще не отслеживает.
3. `git add` кладёт выбранные изменения в индекс.
4. `git commit -m "сообщение"` создаёт коммит из индекса.
5. `git log --oneline` выводит историю: по одной строке на коммит, с сокращённым хешем и сообщением.

```bash
mkdir notes
cd notes
git init
echo "Мои заметки" > README.md
git status
git add README.md
git commit -m "Add README"
git log --oneline
```

После `git init` файл `README.md` в `git status` числится как неотслеживаемый (untracked). После `git add README.md` он попадает в раздел «Changes to be committed». После коммита `git status` сообщает, что рабочая копия чистая (nothing to commit, working tree clean).

## Что именно попадает в коммит

Коммит — это снимок состояния файлов, взятый из индекса, а не из рабочей копии. Если вы изменили файл, добавили его через `git add`, а потом изменили ещё раз, в коммит попадёт версия на момент `git add`. Последняя правка останется в рабочей копии и в `git status` будет показана как не добавленная в индекс. Чтобы сохранить и её, выполните `git add` ещё раз.

Для добавления есть две основные формы:

- `git add имя-файла` добавляет конкретный файл;
- `git add .` добавляет все новые, изменённые и удалённые файлы текущего каталога и вложенных каталогов.

Вторая форма удобна, но требует внимания: перед коммитом проверяйте `git status`, чтобы в индекс не попало лишнее.

## Типичные ошибки

- **Забыли `git add`.** Команда `git commit` без изменений в индексе ничего не сохранит и сообщит, что коммитить нечего.
- **Закоммитили лишнее.** Временные файлы, зависимости и секреты (пароли, ключи) не должны попадать в историю. Для временных файлов используйте `.gitignore`. Секрет, однажды попавший в историю, считайте скомпрометированным и меняйте.
- **Бессмысленное сообщение** вроде «fix» или «update». Хорошее сообщение коротко отвечает на вопрос, что изменилось и зачем.
- **Один огромный коммит** со всем сразу. Лучше делать небольшие коммиты, каждый из которых решает одну задачу.
- **Запуск `git init` не в той папке.** Если случайно создали репозиторий внутри другого репозитория, получится вложенный репозиторий, и внешний будет вести себя неожиданно. Перед `git init` проверьте, где вы находитесь.
