# ProgChecklist — инструкции для Claude Code

Сайт «Карта программиста»: подробный чеклист тем программирования (будущий курс), с монетизацией.
Язык интерфейса и контента — русский. Код, коммиты, комментарии — английский.

## Старт любой сессии (обязательно)
1. Прочитай `docs/CONTEXT_MAP.md` — там сказано, где какая информация.
2. Прочитай `docs/STATUS.md` — текущее состояние и что делалось в прошлый раз.
3. Дальше читай только то, что нужно для текущей задачи (по карте). Не загружай все docs подряд.

## Роли и модели
- **Главная сессия = Opus (оркестратор).** Запускается как `claude --model opus`.
  Планирует, режет задачи, пишет ТЗ для исполнителя, проверяет результат, ведёт документацию.
  Opus сам продакшн-код не пишет, кроме мелких правок (≤ ~10 строк) после ревью.
- **`implementer` (Sonnet)** — пишет код и тесты по одной задаче из `docs/BACKLOG.md`.
- **`reviewer` (Opus)** — независимое ревью диффа против критериев приёмки, со свежим контекстом.
- Не задавай переменную окружения `CLAUDE_CODE_SUBAGENT_MODEL` — она перебивает модели из `.claude/agents/`.

## Рабочий цикл (команда `/next`)
Выбрать задачу → ТЗ → implementer → `dotnet build` + `dotnet test` → reviewer → исправления (макс. 2 круга) → коммит → обновить BACKLOG и STATUS.
Подробно — `.claude/commands/next.md`.

## Жёсткие правила
- Одна задача = один коммит (Conventional Commits). Ветка `main`, без force push.
- Красные тесты/сборка = задача не сделана. Не отключать и не удалять тесты, чтобы стало зелёным.
- Не выходить за рамки текущей фазы из `docs/ROADMAP.md`. Конец фазы = СТОП и запрос ревью у человека.
- Архитектурное решение (новая библиотека, смена подхода, схема БД) → запись в `docs/DECISIONS.md` до реализации.
- Не менять `slug` в `content/topics.json` без миграции — это ID в URL и прогрессе пользователей.
- Без участия человека нельзя: платёжные системы, реальные ключи/секреты, домены, деплой в прод, регистрация в сервисах.
  Такие задачи помечаются `needs-human` и пропускаются.
- Секреты только через user-secrets / переменные окружения. Никогда в репозиторий.
- Если застрял (2 неудачных круга ревью, непонятное требование) → статус задачи `blocked` с причиной в STATUS.md, переход к следующей.

## Команды
- Сборка: `dotnet build`
- Тесты: `dotnet test`
- Запуск: `dotnet run --project src/ProgChecklist.Web`
- Окружение: Windows 11, PowerShell. Пути — через `Path.Combine`, не хардкодить `\` или `/`.
