# Руководство для авторов контента

Как добавить к теме урок и ссылки «Где изучить». Решения, на которых это держится, — ADR-10 (Markdig) и ADR-11 (раскладка контента) в `docs/DECISIONS.md`.

Контент проверяется при старте приложения и в тестах: ошибка в файле = сайт не стартует, CI красный. Это нарочно — битый контент не должен попасть в прод.

## Где что лежит

| Что | Файл | Обязательно |
|---|---|---|
| Урок темы | `content/lessons/{section}/{topic}.md` | нет |
| Ссылки «Где изучить» | `content/resources.json`, ключ `"{section}/{topic}"` | нет |
| Список тем и slug'и | `content/topics.json` | только читать |

`{section}` и `{topic}` — slug'и из `content/topics.json`, **точно в том же регистре** (нижний). Slug'и не менять: это URL и ключи прогресса пользователей.

## Урок

### Правила
- Имя файла — `{topic}.md` в папке `{section}`, расширение `.md` строчными буквами. `.MD`/`.Md` — ошибка старта (на всех ОС одинаково). Файлы с другими расширениями (`.txt`, `.markdown`) игнорируются.
- Урок без темы в каталоге, пустой файл, не канонический регистр пути — ошибка старта.
- Заголовки начинаются с `##`. Заголовок `#` запрещён (ошибка старта): `h1` на странице — название темы.
- **Первый абзац** (обычный абзац верхнего уровня, не цитата и не список) становится meta description страницы в поиске — обрезается до 160 символов. Поэтому:
  - называйте тему и говорите конкретно, о чём она: 80–160 символов;
  - без шаблонных зачинов («В этом уроке разберём…», «Введение.») — такие описания одинаковые и бесполезные;
  - одинаковые первые абзацы у двух уроков уронят тест уникальности описаний.
- Сырой HTML не работает: он выводится как текст. Пишите только Markdown.
- Внешние ссылки — `https://`. Технически пропускаются также `http://`, `mailto:` и относительные, но `http://` не используйте. `javascript:`, `data:`, `vbscript:` и прочие схемы — ошибка старта, в том числе замаскированные (`java&#115;cript:`, ссылки-сноски).
- Доступно: заголовки `##`–`######` (на практике хватает `##`–`###`), абзацы, списки, списки-задачи (`- [ ]`), `код` и блоки кода с языком, таблицы, цитаты, ссылки, картинки по `https://`.
- Пишите по-русски, термины — как принято в индустрии (commit, branch). Факты сверяйте с официальной документацией.

### Пример урока

Файл `content/lessons/git/init-add-commit.md`:

<!-- example:lesson git/init-add-commit -->
````markdown
Команды git init, git add и git commit создают репозиторий, отбирают изменения в индекс и сохраняют их снимком в истории проекта.

## Зачем это нужно

Git хранит историю как цепочку коммитов. Каждый коммит — снимок всех файлов из индекса с автором, датой и сообщением.

## Три шага

1. `git init` — создаёт в папке скрытый каталог `.git` с пустой историей.
2. `git add <файл>` — кладёт текущее состояние файла в индекс (staging area).
3. `git commit -m "сообщение"` — записывает индекс в историю.

```bash
git init
git add README.md
git commit -m "Add README"
```

| Команда | Что меняет |
|---|---|
| `git add` | индекс |
| `git commit` | историю |

> Коммит сохраняет то, что лежит в индексе, а не всё, что изменено в папке.

Подробнее — в [документации Git](https://git-scm.com/docs/git-commit).
````

## Ссылки «Где изучить»

### Формат записи

```
"{section}/{topic}": [
  { "title": "…", "url": "https://…", "kind": "docs", "lang": "en", "free": true, "affiliate": false }
]
```

| Поле | Обязательно | Значения |
|---|---|---|
| `title` | да | непустой текст ссылки — понятное название материала, не «тут» и не URL |
| `url` | да | только `https://` |
| `kind` | да | `docs`, `article`, `video`, `course`, `book`, `practice` (строчными) |
| `lang` | да | `ru`, `en` (строчными) |
| `free` | нет, по умолчанию `true` | бесплатный ли материал |
| `affiliate` | нет, по умолчанию `false` | партнёрская ли ссылка |

### Правила
- Неизвестная тема, пустой `title`, не-`https` URL, неизвестный `kind`/`lang`, повтор URL внутри темы, **неизвестное поле** (опечатка вроде `afiliate`) — ошибка старта.
- URL, отличающиеся только `#якорем`, считаются одним и тем же — две ссылки на разные разделы одной страницы в одну тему не добавить.
- Порядок в файле = порядок на странице. Первым ставьте лучший материал, обычно официальную документацию.
- Без трекинг-параметров (`utm_*`, `ref=` и т. п.) в обычных ссылках.
- Источники: официальная документация и известные проверенные ресурсы. Ссылка должна открываться без регистрации, если `free: true`.

### Партнёрские ссылки
- Только с `"affiliate": true` — тогда на сайте ставится `rel="sponsored noopener"`, пометка «партнёрская ссылка» и пояснение под списком.
- Выбор партнёров, регистрация в программах, реферальные ссылки и маркировка рекламы — **только человек** (задача P2-08, `needs-human`). Агенты партнёрские ссылки не добавляют.
- Партнёрская ссылка не должна вытеснять бесплатный официальный материал с первого места.

## Как проверить

1. Сборка: `dotnet build`.
2. Тесты: `dotnet test`. На машине со Smart App Control — через WSL: `powershell -ExecutionPolicy Bypass -File scripts/test-wsl.ps1` (ADR-9). Тесты загружают реальные `content/lessons` и `content/resources.json`, проверяют уникальность заголовков и описаний всех страниц.
3. Посмотреть глазами: `dotnet run --project src/ProgChecklist.Web` (или `scripts/run-wsl.ps1`) и открыть `/{section}/{topic}` — урок, блок «Где изучить», бейдж «урок» в чеклисте; проверить светлую и тёмную тему и узкий экран.

Примеры из этого файла проверяются тестом `ContentGuideExamplesTests`: если меняете пример, он по-прежнему должен проходить валидацию.
